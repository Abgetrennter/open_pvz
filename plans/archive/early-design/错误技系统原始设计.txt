# 植物大战僵尸同人游戏：错误技系统技术设计文档（整合版）

## 一、核心设计哲学

### 1.1 效果即一等公民
将 **效果（Effect）** 作为系统的最小可组合单元，而非函数。每个效果是**可递归配置的节点**，通过"槽位"机制实现嵌套组合（如`shoot`效果包含`on_hit`槽位，可填入`explode`/`damage`等子效果）。这是整个系统无限扩展的基石。

### 1.2 触发器与效果完全解耦
触发器是 **"事件插座"** ，只回答"何时触发"（`periodically`/`when_damaged`/`on_death`等）；效果是 **"执行策略"** ，只回答"做什么"（伤害/治疗/召唤等）。两者通过配置文件动态绑定，而非硬编码。

### 1.3 数据驱动 + 插件化扩展
所有机制（触发器/效果/策略）通过**JSON配置**定义，通过**策略注册表**绑定执行逻辑。新增机制 = 添加JSON + 注册策略，**无需修改核心代码**，支持热更新与社区MOD。

## 二、技术架构总览

```
┌─────────────────────────────────────────────────────────────┐
│                    植物生成器（三层递进）                      │
│  1. 抽取触发器 → 2. 绑定效果树根节点 → 3. 递归填充槽位        │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    运行时植物实例                             │
│  - Plant基类（位置/生命值等通用属性）                        │
│  - TriggerComponent：持有1-2个触发器实例                      │
│  - EffectTree：由EffectNode构成的深度≤3的递归树               │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    事件驱动执行引擎                            │
│  核心层广播硬编码事件 → 触发器订阅 → 条件检查 → 执行效果树      │
└─────────────────────────────────────────────────────────────┘
```

## 三、核心机制详解

### 3.1 触发器系统

**静态定义（TriggerDef）**
```json
{
  "trigger_id": "when_damaged",
  "event_name": "plant.damaged",  // 硬编码事件名
  "max_bound_effects": 1,
  "condition_params": [
    {"name": "damage_threshold", "type": "int", "min": 0, "max": 999},
    {"name": "probability", "type": "float", "min": 0.0, "max": 1.0}
  ],
  "tags": []  // 如[ManualTrigger]用于互斥检测
}
```

**动态实例（TriggerInstance）**
- 植物生成时从`TriggerDef`克隆，填充随机参数值
- 自动订阅同名事件，独立管理冷却与状态

**执行策略（TriggerStrategy）**
- **纯函数**：`bool CheckCondition(eventData, params, plantState)`
- **短路设计**：阈值/概率/冷却任一不满足立即返回`false`
- **防连击**：内置`last_triggered_time`限制，单植物单触发器间隔≥0.05秒

**互斥规则**
- `[ManualTrigger]`标签（如`on_click`）一个植物最多1个
- 若随机生成时冲突，静默丢弃第二个

### 3.2 效果系统

**静态定义（EffectDef）**
```json
{
  "effect_id": "shoot",
  "slots": [
    {
      "name": "speed",
      "type": "value",
      "value_type": "float",
      "min": 5.0,
      "max": 20.0
    },
    {
      "name": "on_hit",
      "type": "effect",
      "allowed_types": ["damage", "explode", "summon", "null"]
    }
  ]
}
```

**动态实例（EffectNode）**
```json
{
  "effect_id": "shoot",
  "params": {"speed": 13.7},
  "children": {
    "on_hit": {
      "effect_id": "explode",
      "params": {"radius": 3},
      "children": {"on_explosion": {"effect_id": "null"}}
    }
  }
}
```

**执行策略（EffectStrategy）**
- **无状态**：接收`Context`快照（只读） + `State`字典（可写），返回执行结果
- **延迟绑定**：子弹/召唤物等实体在命中时才触发子效果，惰性构建
- **DFS遍历**：递归执行，连锁深度>5强制终止

### 3.3 三层生成器

**第一层：触发器抽取**
```plaintext
1. 随机决定数量 (1-2个)
2. 从TriggerDef库按权重抽取
3. 检查标签互斥：[ManualTrigger]最多1个
4. 为每个TriggerInstance随机填充condition_params
```

**第二层：效果树根绑定**
```plaintext
对每个触发器：
  1. 随机决定绑定效果数 (1-max_bound_effects)
  2. 从EffectDef库按权重选根效果ID
  3. 调用BuildEffectTree(root_id, depth=0)
```

**第三层：递归构建效果树**
```plaintext
函数 BuildEffectTree(effect_id, depth):
  1. 获取EffectDef的slots定义
  2. 对每个槽位：
     a. 值槽位 → 随机生成值
     b. 效果槽位：
        i. depth >= 3 → 强制填null（树终止）
        ii. 否则按allowed_types权重随机选（含null）
        iii. 若选到子ID → 递归调用BuildEffectTree(child_id, depth+1)
  3. 返回填充后的EffectNode
```

**权重调控**
- **Level 1（触发器）**：`periodically:100` > `when_damaged:60` > `on_death:30` > `on_click:15`
- **Level 2（效果）**：`shoot:100` > `damage:80` > `explode:25` > `summon:20`
- **Level 3（槽位填充）**：如`shoot.on_hit`中`null:50` > `damage:30` > `explode:15` > `summon:5`

## 四、关键实现要点

### 4.1 数据结构设计

**组件模式（Component Pattern）**
- `Plant`基类：位置、生命值等通用属性
- `TriggerComponent`：持有`List<TriggerInstance>`
- **无继承**：所有功能通过配置动态添加组件

**快照式上下文**
```csharp
class Context {
  public Vector3 position;      // 事件位置
  public Entity target;         // 目标实体
  public int chainDepth;        // 连锁深度（只读）
  // ... 其他只读数据
}

class PlantState {
  public Dictionary<string, object> values;  // 充能、冷却等可写状态
}
```

### 4.2 事件系统

**硬编码事件列表（核心层）**
```plaintext
plant.planted / plant.died / plant.damaged
plant.sun_produced / plant.clicked
projectile.hit / zombie.died / game.tick
```

**广播规范**
- 在生命周期关键节点无条件广播
- 事件数据仅包含客观事实，无业务逻辑
- 触发器策略负责过滤与决策

### 4.3 无限循环防护体系

**静态规则（预生成阶段）**
- 深度上限=3：效果树递归深度超限自动终止
- 互斥黑名单：如`on_death`不能绑定`治疗自身`

**运行时防护**
- 事件链深度≤5：超限时静默丢弃，无日志/特效，玩家感知为"自然停止"
- 召唤物隔离：召唤物打`[Summoned]`标签，触发器可配置`ignore_summoned:true`
- 事件源追踪：`eventData.sourceId`防止自触发（如`when_damaged`不响应自己造成的伤害）

**性能优化**
- 函数缓存：轨迹/公式函数生成一次，后续纯数学计算
- 零反射：策略实例启动时注册到字典，运行时O(1)查找
- 事件合并：同帧同类事件合并，减少调用次数

### 4.4 命名与可视化

**熵灌注命名法**
```plaintext
输入：效果树遍历串 + 时间戳
输出：§kQ3.9xFα  （11字符乱码）
  - Prefix §/¶/†：稀有效果数量决定
  - Body 7字符：随机62进制
  - Suffix α/Ω/β：触发器类型（Periodic/Death/Damaged/Click）
```
- **相同输入→相同输出**，可复现
- 玩家通过`§`和`α`判断稀有度与触发方式，培养Mastery

**纯文本图标（Demo）**
- 底色：触发器类型（Periodic=绿, Death=红, Damaged=橙）
- 中心字母：根效果ID首字母（S=Shoot, E=Explode, U=Summon）
- 四角徽章：Suffix符号

**Tooltip动态解码**
```
§kQ3.9xFα
━━━━━━━━━
稀有度: §（含稀有效果）
触发: α（周期性，每3秒）
结构: 发射 → 爆炸 → 召唤
深度: 3层
```

### 4.5 扩展性与社区生态

**配置文件驱动**
- 所有机制（触发器/效果/策略）通过JSON/XML定义
- 支持热更新：运行时重载配置，无需重启游戏

**社区分享机制**
- 植物存档 = 效果树JSON + 遍历串 + 名称
- 分享码 = Base64(遍历串)
- 导入时反序列化，重新生成名称和图标（确保版本兼容）

**MOD开发流程**
1. **新增触发器**：在核心层PR添加事件广播 → 配置TriggerDef → 注册TriggerStrategy
2. **新增效果**：配置EffectDef → 注册EffectStrategy → 可在其他效果的allowed_types中引用
3. **新增分类**：调用`TypeRegistry.RegisterCategory("death_vfx", "value")`动态注册

## 五、下一步游戏设计方向

### 5.1 玩法模式演进

** Roguelike冒险模式 **
- 每局游戏植物完全随机生成，玩家从3选1
- 引入"道具池污染"机制：劣质机制被选中后，后续出现概率降低
- 局外成长：解锁新机制到库中，或提升特定机制权重

** 沙盒创造模式 **
- 开放完全自定义界面，玩家可手动搭建效果树
- 社区挑战：每周限定机制池，玩家创作最强植物
- 图鉴收集：生成过的植物自动存入图鉴，可查看稀有度与解锁进度

** 异步PvP模式 **
- 玩家A设计植物 → 分享码 → 玩家B用该植物挑战关卡
- 排行榜：根据通关时间/难度对植物评分，而非玩家操作

### 5.2 机制深度扩展

** 二级触发器体系 **
- 引入"触发器前置条件"：如`when_damaged`需先满足`hp_below:0.5`
- 触发器组合逻辑：`and`/`or`/`xor`，支持复杂状态机

** 环境交互机制 **
- 地形效果：特定格子触发`on_plant_on_ice`/`on_plant_on_lava`
- 天气系统：`game.weather_changed`事件驱动全局机制切换

** 经济循环闭环 **
- 阳光作为可消耗资源触发手动技能：玩家主动"花费阳光"触发`on_click`效果
- 负面效果：某些植物产阳光时触发`damage_self`或`slow_all_plants`

### 5.3 视觉与叙事包装

** 赛博故障美学 **
- UI裂纹、像素抖动、颜色偏移，强化"错误技"主题
- 植物生成时显示"数据流"动画，熵灌注过程可视化

** 叙事碎片化 **
- 每株乱码名称的植物附带一句"错误日志"："`§kQ3.9xFα: 数据溢出，协议破裂`"
- 收集特定稀有度植物解锁隐藏剧情

### 5.4 平衡性与玩家引导

** 动态难度调整 **
- 系统根据玩家当前植物组合强度，自动调整僵尸波次
- 若生成植物过弱，后续关卡阳光掉落率提升；若过强，引入"反制僵尸"

** 渐进式解锁 **
- 初始仅开放基础机制（shoot/damage/periodically）
- 通过完成成就解锁稀有机制（explode/summon/on_death）
- 避免新手期被复杂机制淹没

** "保底"机制 **
- 完全随机模式下，每10次生成必出至少一个稀有（§）植物
- 模板模式下，根据玩家偏好动态调整权重（如常用攻击型则提升防御型权重）

### 5.5 技术优化方向

** 代码生成器 **
- 根据JSON配置自动生成C#策略骨架，减少手写样板代码

** 可视化编辑器 **
- 节点式UI拖拽构建效果树，实时预览遍历串与名称

** 性能分析器 **
- 统计每个机制组合的触发频率与耗时，识别性能热点
