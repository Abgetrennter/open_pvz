## TL;DR

当前 OpenPVZ 的基础运行时不是空白状态：Mechanic-first 主链、battle mode v1、规则基础设施、GridItem 第一片、原版僵尸 25 个目标批次、原版植物 46/49 资源卡片和大量专项验证都已经进入主干。

真正剩余的高价值缺口集中在五类：

1. **原版植物阻塞项**：Garlic 换道、Umbrella Leaf 防护、Imitater 卡片复制。
2. **已有最小实现但缺原版精度**：Doom-shroom crater 绑定、Cob Cannon projectile/reload 精度、Sun-shroom 长时长成长验证、coin/silver/gold taxonomy。
3. **僵尸与特殊敌人延后范围**：Bobsled Team、Dr. Zomboss、Zombotany，以及部分已实现僵尸的精确交互。
4. **模式与场地系统**：大量小游戏、Zen Garden/Tree of Wisdom、完整 fog/visibility、ice trail、ladder 持久物件、vase/portal 等。
5. **表现与外循环**：完整 reanim 表现、音频映射、图鉴/商店/存档等不属于当前机制主线，但影响“像原版”的完整体验。

## 事实源与优先级

### 三方来源

| 来源 | 路径 | 本文用途 |
|------|------|----------|
| 原版规格优先源 | `vendor/de-pvz/` | 枚举、数值、行为条件、tick 语义、模式列表 |
| Godot 表达参考 | `vendor/PVZ-Godot-Dream/` | 观察组件拆分、节点组织、UI/动画/模式工程落点 |
| OpenPVZ 当前实现 | 当前仓库 runtime/data/validation | 判断是否已经有正式能力、资源、验证和文档归属 |

### 口径规则

- 原版行为以 `vendor/de-pvz/` 为优先来源。
- `PVZ-Godot-Dream` 只作为 Godot 组织方式参考，不能覆盖原版语义。
- 当前完成度以 runtime、资源树、`tools/formal_content_validation_map.json` 和验证场景为准。
- `plans/original-plant-protocol-gaps.md` 中部分内容已经被后续实现推进超越，本文将其作为历史线索，不机械沿用旧状态。
- 本文不建议为单个实体新增 `BattleManager` 特判；所有新增能力应翻译到 Mechanic、Effect、Controller、Movement、BattleModeHost、Board/GridItem 或 CardState 边界。

## 植物侧缺口

### P0-1 Garlic：换道机制

| 维度 | 记录 |
|------|------|
| 原版锚点 | `vendor/de-pvz/ConstEnums.h:SeedType::SEED_GARLIC`，`vendor/de-pvz/Lawn/Plant.cpp:gPlantDefs[]`，`Plant::AnimateGarlic()` |
| Godot 参考 | `vendor/PVZ-Godot-Dream/scripts/character/plant/plant_037_garlic.gd` 中调用 `attack_zombie.update_lane_on_eat_garlic()` |
| 当前 OpenPVZ | 无 `archetype_original_garlic` / `card_original_garlic`；无 lane reroute effect/rule module |
| 缺失能力 | 被啃咬后让攻击者换到相邻 lane，并保持 deterministic 行为 |
| 建议落点 | 新增 `Effect.lane_reroute` 或 battle rule module；由 `when_damaged` / 攻击标签触发，目标为 `event_source` |
| 验证建议 | `plant_original_garlic_validation`：生成 Garlic 与僵尸，僵尸啃咬后 lane_id 改变，SpatialIndex 更新，且无 BattleManager 实体特判 |

关键设计点：

- 需要明确“啃咬”与普通 damage 的区分，至少要有 damage tag / attack type。
- 换道方向应由可配置策略决定，例如优先上/下、随机但走 battle_seed、边界 lane fallback。
- lane 变化不应直接写 `position.y`，应通过 board metrics / movement command 同步 lane_id、空间索引和视觉位置。

### P0-2 Umbrella Leaf：特定攻击防护

| 维度 | 记录 |
|------|------|
| 原版锚点 | `vendor/de-pvz/ConstEnums.h:SeedType::SEED_UMBRELLA`，`vendor/de-pvz/Lawn/Plant.cpp:UpdateUmbrella()`，Bungee 相关 `mHitUmbrella` 流程 |
| Godot 参考 | `vendor/PVZ-Godot-Dream/scripts/character/plant/plant_038_umbrella_leaf.gd` 通过区域进入触发 `be_umbrella_leaf()` |
| 当前 OpenPVZ | 无 `archetype_original_umbrellaleaf` / `card_original_umbrellaleaf`；无 target protection / attack guard 协议 |
| 缺失能力 | 对指定范围内目标拦截 Bungee/Catapult 等特定攻击类型 |
| 建议落点 | `Controller.core.protect_targets` 或 `Effect.intercept_attack`，攻击事件需携带 attack_type / trajectory / source tags |
| 验证建议 | `plant_original_umbrellaleaf_validation`：Bungee/Catapult 攻击被拦截，普通 bite 不被拦截，保护范围外不生效 |

关键设计点：

- 防护不是普通免伤，应有“攻击被取消/转向/失败”的事件语义。
- Umbrella 不应直接认识 Bungee 类名；应匹配攻击标签，如 `bungee`, `catapult`, `overhead`。
- 需要处理多个 Umbrella 覆盖同一目标时的优先级和去重。

### P0-3 Imitater：卡片复制协议

| 维度 | 记录 |
|------|------|
| 原版锚点 | `vendor/de-pvz/ConstEnums.h:SeedType::SEED_IMITATER`，`Plant::PlantInitialize(..., theImitaterType)`，`Plant::ImitaterMorph()`，`Plant::GetCost()`，`Plant::GetRefreshTime()` |
| Godot 参考 | `vendor/PVZ-Godot-Dream/scripts/ui/card/card_slot/card_slot_norm/card_slot_candidate.gd`，`card_imitater.gd`，`plant_999_imitater.gd` |
| 当前 OpenPVZ | 无 Imitater card clone 协议；无 clone card 的独立 cooldown/cost/identity 表达 |
| 缺失能力 | 选卡阶段选择被复制植物，战斗中以独立卡片进入 CardState，放置后变形成目标 archetype |
| 建议落点 | Card layer clone/proxy 协议，而不是实体运行时特判；`CardDef` 支持 clone_target 或 runtime-selected target |
| 验证建议 | `plant_original_imitater_validation`：原卡和复制卡可同时在手牌中，cooldown 独立，放置生成目标 archetype 并带 imitater metadata |

关键设计点：

- Imitater 的主要复杂度在 card/deck/choose 阶段，不在普通 plant runtime。
- 不应只新增 `archetype_original_imitater` 后直接 `spawn_entity`；那会绕开卡片复制语义。
- 需要决定复制卡 cost / cooldown 取目标卡、Imitater 自身，还是当前模式 override。

### P1-1 Doom-shroom：crater 绑定与持续禁种

| 维度 | 记录 |
|------|------|
| 原版锚点 | `vendor/de-pvz/Lawn/Plant.cpp:UpdateDoomShroom()`，`Plant::DoSpecial()` 中 `AddACrater(...)->mGridItemCounter = 18000` |
| Godot 参考 | 可参考 GridItem / 场地物件组织，不建议照抄实体特判 |

- `grid_item_crater_validation` 证明了通用 GridItem 能力，不等于 Doom-shroom 已完成原版绑定。
- 若只补手动 remove，不足以表达原版持续时间；需要可控仿真时间下的 TTL 验证。

## 每类缺口的最小验证模板

| 缺口类型 | 验证事件建议 | 负向断言 |
|----------|--------------|----------|
| lane reroute | `entity.lane_changed`、`movement.commanded` | 非 bite damage 不触发；边界 lane 不越界 |
| attack protection | `attack.intercepted`、`entity.protected` | 普通 bite 不被拦截；范围外不拦截 |
| card clone | `card.clone_resolved`、`placement.accepted` | clone target 为空时拒绝；原卡 cooldown 不被 clone 共享 |
| crater TTL | `grid_item.spawned`、`grid_item.removed` | crater 期间 placement rejected；无 combat damage/death |
| projectile precision | `projectile.spawned`、`projectile.hit`、`entity.manual_skill_rejected` | reload 中不能发射；无 ready 不产生伤害 |
| field modifier | `field_modifier.added`、`field_modifier.removed` | 不影响无关 lane/slot |
| boss mode | `mode.objective_progressed`、`battle.victory` | Boss 未死前不能 victory |

## 开放问题

1. Garlic 的换道应作为通用 `Effect`，还是作为 battle rule module？如果未来有更多“强制路径改变”机制，通用 Effect 更合适。
2. Umbrella 的防护范围应是 slot 半径、lane/slot 矩形，还是通过 spatial query radius 表达？
3. Imitater 的 clone card 是否应拥有独立 card_id？建议是独立 card instance，保留 target archetype metadata。
4. Doom crater 的持续时间是否按原版 tick 精确，还是先用可配置 duration 表达？
5. Cob Cannon 是否应把 manual skill 抽象为可配置 skill definition，避免继续膨胀 `manual_entity_skill` 的硬编码参数？
6. Bobsled Team 是否需要 group entity，还是可由 wave composer 一次生成多个 linked zombie 表达？
7. Dr. Zomboss 是引擎内置 boss 能力，还是作为官方扩展包/模式样例落地？
