# 视觉反馈层

- 状态：当前事实

> 本文描述视觉反馈层当前已成立的协议、注册表、宿主与验证入口。视觉反馈层是规则引擎之外的正交支撑层：它只解释已经发生的事实，不参与产生事实。设计过程与任务拆解见 `plans/visual-feedback-layer/`（实现对照结论见其 07 号文档）。

---

## 一句话定义

> 规则事实驱动表现：视觉层通过统一入口订阅 `EventBus` 事件与实体状态，把它们解释为动画、FX、音频请求和 actor 显示变化，但不反向修改规则结果。

---

## 职责与边界

视觉反馈层**只允许**：

- 监听语义事件（`projectile.hit`、`entity.damaged`、`entity.died` 等）
- 读取实体状态、`ProjectileMoveResult`、`RuntimeSpec` 视觉参数与 battlefield preset
- 产生动画播放、FX 生成、音频 cue 请求、闪白/染色 overlay、`z_index` 调整

视觉反馈层**不得**：

- 修改伤害值、目标选择、`EffectExecutor` 执行顺序或结果
- 改变状态持续时间、改写 `EventData` 规则事实
- 阻止实体死亡或销毁
- 让非视觉验证依赖可见像素

失败语义：任何视觉子系统失败都必须降级为 no-op 并记录，不得抛出到战斗主链。

## 组成部分

### VisualCue：事件反馈（一次性）

| 对象 | 位置 | 职责 |
|---|---|---|
| `VisualCueDef` | `scripts/core/defs/visual_cue_def.gd` | cue 贡献项资源：`id / listen_event / filters / actions / tags` |
| `VisualCueRegistry` | `autoload/VisualCueRegistry.gd` | slot `visual_cues`，trust `data_only`；内置 6 个 `core.*` cue |
| `VisualFeedbackHost` | `scripts/visual/visual_feedback_host.gd` | 统一订阅固定事件集，按 `filters` 匹配 cue，把 action 交给 runner；每步写入 `DebugService.record_visual_event` |
| `VisualActionRunner` | `scripts/visual/visual_action_runner.gd` | 执行内置 action：`spawn_fx / play_audio / flash_actor / play_actor_animation / attach_fx / screen_overlay / play_actor_action / play_actor_action_sequence / play_actor_state` |

`VisualFeedbackHost` 固定订阅的事件：

```text
projectile.spawned / projectile.hit / projectile.expired
entity.damaged / entity.died / entity.status_removed
placement.accepted / combat_action.phase
```

cue `filters` 支持：`core_values`（任意 core 字段精确匹配）、`source_kind / target_kind`、`source_archetype_id / target_archetype_id`、`tags`、`move_mode`、`profile_id`。

### VisualProfile：实体表现（持续）

| 对象 | 位置 | 职责 |
|---|---|---|
| `VisualProfileDef` | `scripts/core/defs/visual_profile_def.gd` | `actor_scene / animation_map / state_animation_map / action_animation_map / status_visual_map / damage_stage_defs / shadow_policy / z_policy / default_scale / ground_offset` |
| `VisualProfileRegistry` | `autoload/VisualProfileRegistry.gd` | slot `visual_profiles`；内置 `core.placeholder_plant / placeholder_zombie / placeholder_projectile` |
| `VisualActorComponent` | `scripts/components/visual_actor_component.gd` | 实体可选挂载的表现组件：实例化 actor scene、状态→动画映射、受击闪白、damage stage、投射体影子跟随 |

`EntityFactory` 仅当 archetype/spec 提供 visual profile 时挂载 `VisualActorComponent`；无 profile 实体保持既有 fallback 表现（如 `ProjectileRoot._draw()`）；profile 加载失败记录 warning 并继续创建实体。

当前消费状态：

- `state_animation_map / action_animation_map`：已消费（reanim actor 自带 `play_state / play_action` 优先，未命中回落 `AnimationPlayer`）。
- `damage_stage_defs`：已消费（按 `threshold_ratio` 每阶段一次，支持 modulate 与子节点显隐；阶段内 `spawn_fx` 为 log-only）。
- `status_visual_map`：**字段已定义、消费方未实现**（状态 overlay 合成是当前已知缺口，见文末"当前边界"）。
- `shadow_policy`：已消费（投射体影子跟随 `get_ground_position()`）。

### VisualStageLayer：层级与环境

| 对象 | 位置 | 职责 |
|---|---|---|
| `VisualLayerPolicy` | `scripts/visual/visual_layer_policy.gd` | 11 层常量与集中 `LAYER_BASE`（ground=0 … ui=10000），`ROW_STRIDE=100`；`z_index = layer_base + lane_id * row_stride + local_offset` |
| `VisualStageLayerService` | `scripts/visual/visual_stage_layer_service.gd` | 计算 z_index、提供 layer host、`apply_visual_preset` 接入 battlefield preset；由 `BattleManager` 初始化与清理 |

层级固定为：`ground / shadow / field_object / plant / zombie / projectile / world_fx / fog_weather / preview / screen_fx / ui`。`lane_id = -1` 使用安全默认层级。battlefield visual preset 当前 v1 口径为**只读取并记录**（`data/combat/environments/` 已有 6 个环境资源），完整背景系统后置。

### AudioCue：音频请求

`AudioCueDef` + `AudioCueRegistry`（slot `audio_cues`，trust `data_only`）。v1 只作为 visual action 的请求目标（当前内置 `core.silent`），不定义音频播放主协议。

## 扩展槽接入

四个视觉 register kind 已进入 `ExtensionPackCatalog.ALLOWED_REGISTER_KINDS`：

```text
visual_cues / visual_fx / audio_cues / visual_profiles
```

规则：

- 全部 trust level 为 `data_only`；扩展包不得注册或覆盖 `core.*`。
- 重复 id、非法 def、越权信任级别拒绝并记录 `protocol.issue`。
- v1 不允许扩展包注册任意视觉脚本 action（`visual_action_strategies -> trusted_runtime` 为后置预留）。
- 扩展包资源路径：`extensions/<pack>/data/combat/visual_cues|visual_fx|audio_cues|visual_profiles/*.tres`。
- 资源缺失时 action 降级 no-op + visual warning，不抛 fatal。

| 场景 | 层 | 覆盖 |
|---|---|---|
| `visual_registry_smoke` | smoke | 四 registry 初始化无 `protocol.issue` |
| `visual_cue_projectile_hit_smoke` | smoke | `projectile.hit` 触发预期 action request |
| `visual_action_types_smoke` | smoke | 内置 action 类型逐一可执行 |
| `visual_projectile_projection_smoke` | smoke | 本体 `projected_position` / 影子 `ground_position` 分离 |
| `visual_actor_profile_smoke` | smoke | actor 挂载、状态动画 request、damage stage |
| `visual_slot_guardrail` | smoke+guardrail | 重复 id / `core.*` 覆盖 / 非法 def 拒绝 |
| `visual_extension_pack_smoke` | smoke | data-only 扩展包正向注册可查询 |

以上场景均登记于 `tools/validation_scenarios.json` 并进入公开批量回归。local_private 层另有 reanim 运行时专项场景（属于素材复刻线，见 Reanim 相关文档）。

## 当前边界与已知缺口

- `status_visual_map` 尚无消费方：冰冻/魅惑/睡眠等状态 overlay 的合成顺序（`base_color -> hit_flash -> status_overlay`）未实现，状态视觉当前只能由 actor 内建行为表达。
- 内置 `core.*` FX 的 `fx_scene` 为 null（占位）：`spawn_fx` 实际降级 no-op + log，等待正式素材批次。
- 投射体影子当前为位置锚点占位，可见物绘制待 actor 素材。
- `fog_weather / screen_fx` 宿主为空壳节点，随环境与天气设计批次消费。

以上缺口均为素材侧或已登记后续任务，不构成协议缺口（`status_visual_map` 消费链由任务 `design/visual-status-overlay` 承接）。
